# requirements.lock
# =====================================================================
# См. SECURITY_AND_HARDENING_TODO.md, п.23 ("Dependency versions не
# запинены (>=)"). ">=" в requirements.txt означает, что `pip install`
# в разное время на разных машинах может подтянуть РАЗНЫЕ минорные/
# патч-версии - для scikit-learn/numpy/scipy это не только вопрос
# стабильности сборки, а прямой риск для ВЫДАЧИ МОДЕЛИ: разные версии
# одного и того же алгоритма (например, изменение дефолтного solver'а
# или порядка операций с плавающей точкой) могут дать чуть другие
# author_style_pipeline.joblib-предсказания на одном и том же входе,
# даже без переобучения модели - см. также п.24 ниже про то, почему
# joblib-артефакты и версии их зависимостей должны совпадать в проде
# и при обучении.
#
# ЧЕСТНО ПРО ОГРАНИЧЕНИЯ ЭТОГО ФАЙЛА
# -------------------------------------------------------------------
# Версии ниже, помеченные `# verified` - это фактические версии,
# установленные и проверенные (import + компиляция) в песочнице, где
# готовился этот патч. Версии, помеченные `# NOT VERIFIED HERE` -
# это пакеты, которые в этой офлайн-песочнице установить было
# невозможно (нет доступа в сеть) - их номера версий здесь НЕ
# подтверждены реальной установкой, только скопированы из
# требований `>=` в requirements.txt как временный плейсхолдер.
# Перед тем как полагаться на этот .lock-файл в проде, ОБЯЗАТЕЛЬНО:
#   1. Установите requirements.txt в чистом окружении (с сетью).
#   2. Прогоните `pip freeze` и замените строки "NOT VERIFIED HERE"
#      ниже на реально полученные версии.
#   3. Прогоните полный набор тестов (pytest) на этом зафиксированном
#      наборе версий, прежде чем разворачивать в проде.
# Пины ниже - хорошая отправная точка (реальные версии на день
# подготовки патча), но не замена шагу 1-3 в вашем собственном CI.
